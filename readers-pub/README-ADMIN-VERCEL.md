# Админка на Vercel — без вложений

Схема: админка пишет правки **в ваш репозиторий GitHub** через его API,
Vercel видит коммит и пересобирает сайт сам.

```
админка  →  GitHub (хранилище)  →  Vercel пересобирает  →  сайт обновился
```

Отдельный проект заводить не нужно: админка — папка `admin/` внутри того же
репозитория, открывается по адресу `вашсайт.ру/admin/`.

**Платить не за что:** GitHub бесплатно хранит репозиторий, Vercel бесплатно
пересобирает. Новых сервисов не добавляется.

---

## Шаг 1. Токен GitHub для записи

1. https://github.com/settings/tokens?type=beta → **Generate new token**.
2. Имя: `ReadersPub admin`. Срок — максимальный.
3. **Доступ к репозиторию** → «Только выбранные» → **ReadersPub**.
4. **Разрешения** → **Содержимое (Contents)** → **Чтение и запись**.
5. Создать и скопировать — показывается один раз.

## Шаг 2. Переменные окружения в Vercel

Проект на vercel.com → **Settings → Environment Variables**. Добавить четыре
штуки (для всех окружений: Production, Preview, Development):

| Имя | Значение | Зачем |
|---|---|---|
| `ADMIN_PASSWORD` | ваш пароль входа | вход в админку |
| `ADMIN_SECRET` | длинная случайная строка | подпись сессий, никому не показывать |
| `GITHUB_TOKEN` | токен из шага 1 | запись правок |
| `GITHUB_REPO` | `rsn771/ReadersPub` | куда писать |

Ещё две переменные задавать не нужно — у них правильные значения по умолчанию:
`GITHUB_BRANCH` = `main`, `CONTENT_PREFIX` = `readers-pub`. Их задают, только
если репозиторий или папка переименованы.

Случайную строку для `ADMIN_SECRET` можно получить так:

```bash
python3 -c "import secrets; print(secrets.token_hex(32))"
```

## Шаг 3. Выложить и проверить

```bash
cd ~/Desktop/ReadersPub && git add -A && git commit -m "Админка через GitHub" && git push
```

Vercel пересоберёт сайт. Дальше открыть `вашсайт.ру/admin/`, войти, в
«Редакторе страницы» поменять текст или загрузить фото.

Проверить, что получилось: в репозитории на GitHub появится коммит вида
`admin: фото «card-menu»`, а через минуту-полторы изменение будет видно на сайте.

---

## Что нужно знать про эту схему

**Правка появляется не мгновенно.** Админка делает коммит сразу, но сайту нужно
пересобраться — обычно **40–90 секунд**. В самой админке предпросмотр
показывает новое сразу, посетители увидят после пересборки.

**Каждая правка — коммит в репозиторий.** История правок ведётся сама,
любое изменение можно откатить. Но и история растёт: фото весят, репозиторий
со временем распухает. Для сайта заведения это не проблема ещё долго.

**Размер файла — до 8 МБ.** Ограничение Vercel на размер запроса. Админка
предупредит, если файл больше.

**Репозиторий публичный** — загруженные фото видны всем. Для фотографий зала
и меню это нормально, они и так на сайте. Ничего личного туда не кладите.

**Заявки на бронь** в этой схеме не хранятся на сервере: они уходят в Telegram
или в Яндекс Форму. Раздел «Брони» в админке на Vercel будет пустым — это
ожидаемо, смотреть заявки нужно там, куда они приходят.

## Безопасность — прочитать обязательно

Сейчас вход — это **один пароль**, который проверяется на сервере, а дальше
выдаётся подписанный токен сессии на 12 часов. Пароль по сети ходит один раз,
при входе; дальше — только токен. На Vercel соединение идёт по HTTPS,
так что перехватить его по дороге нельзя.

Чего всё ещё нет и о чём надо помнить:

- **Нет защиты от перебора пароля.** Шестизначный код подбирается машиной
  за часы. Поставьте пароль из 12+ символов с буквами — это одна переменная
  в Vercel, менять код не нужно.
- **Нет второго фактора и нет журнала входов.**
- **Пароль в коде.** В `lib_store.py` оставлено запасное значение для запуска
  без переменных окружения. Репозиторий публичный — значит, это значение
  видно всем. На Vercel его перекрывает `ADMIN_PASSWORD`, поэтому задайте
  там **другой**, не тот, что в коде.

Если админка будет жить в интернете постоянно, следующий разумный шаг —
закрыть `/admin` ещё и на стороне Vercel (Password Protection в настройках
проекта) либо перевести вход на полноценную авторизацию.

## Кнопка «Опубликовать»

В админке сверху всегда висит плашка:

- **«Есть неопубликованные правки»** — вы что-то поменяли, посетители этого
  ещё не видят. Кнопка **«Опубликовать на сайт»** отправляет правки.
- **«Всё опубликовано»** — новых правок нет.
- **«Правки уходят на сайт сразу»** — так выглядит плашка на Vercel: там
  каждое сохранение уже уходит само, публиковать отдельно не нужно.

Кнопка отправляет **только контент** — `content.json` и загруженные фото.
Код сайта она не трогает: случайно отправить незаконченную работу
программиста нельзя.

Если кнопка пишет, что GitHub не принял доступ — один раз выполните в
терминале `git push`, введите логин и токен, дальше кнопка заработает сама.

## Локальная работа — без изменений

```bash
cd readers-pub && python3 server.py
```

Без `GITHUB_TOKEN` админка пишет прямо в файлы проекта, как раньше.
Код хранилища общий (`lib_store.py`), так что поведение одинаковое.
